# Troubleshooting

Use this guide after checking the relevant Azure and GitHub evidence. Use approved access to your Entra, Foundry, networking, and GitHub resources. Do not introduce static credentials, direct Foundry client settings, portal-only APIM edits, or unreviewed traffic changes.

| Symptom | Check | Recovery |
| --- | --- | --- |
| Claude Code cannot authenticate / APIM returns 401 or 403 | Token has configured tenant, audience, `oid`, `tid`, and app role; Azure CLI session and assignment are valid. | Reauthenticate through the approved flow and correct Entra assignment/consent. Use [client auth](client-authentication.md). |
| Public workflow smoke fails | `APIM_BASE_URL` shape is `https://<apim-name>.azure-api.net/claude`; smoke identity has the role. | Inspect workflow evidence and rerun only after correcting Entra or configuration. |
| Private deployment is not releasable | Hosted runners cannot reach private APIM. | Run protected [HA smoke](availability-dr.md) from a labeled in-network runner; retain evidence. |
| 429 responses | Identify per-user RPM, token, concurrency, or Foundry quota pressure. | Tune only from measured capacity/quota evidence. APIM does not retry 429 or trip the circuit breaker. |
| 503 after provider errors | Inspect Foundry/backend 5xx and circuit-breaker telemetry. | Resolve backend cause and allow the one-minute breaker window to close; no POST replay occurs. |
| `/claude/health` succeeds but inference fails | Health is APIM-local only. | Run authenticated count-token and stream smoke, then inspect Foundry/RBAC/preflight. |
| Foundry 401/403 or model error | APIM identity has `Foundry User`; account, endpoint, and all three deployment names match preflight. | Restore the role or deployment; resolve existing model named values before apply. |
| Client canary fails | Managed settings, `APIM_AUDIENCE`, and `APIM_TENANT_ID` are active in the launch environment; Azure CLI can obtain a token in the caller tenant. | Reauthenticate through the approved flow, then rerun [canary](claude-code-canary.md). Its wait mode launches separate processes, not a same-session refresh test; retain a manual long-lived pilot. Managed settings do not export values to the parent shell. |
| Desktop local Gateway configuration editor errors after update | Desktop `2.9939.4` editor expects `entries.map`; runtime selects the applied profile via `appliedId`. Check whether `configLibrary/_meta.json` is missing `entries` while the applied UUID profile is intact. | Fully quit Desktop, then follow the [local metadata recovery](windows-desktop-pilot.md#local-metadata-recovery-after-a-desktop-update). Relaunch and verify manually; script success does not establish GUI recovery. |
| DNS/failover issue | Separate APIM health from Foundry health; confirm operator traffic change and private/public DNS path. | Follow [availability and DR](availability-dr.md). The workflow observes but never changes traffic. |
| Plan/apply stops on summary or destructive change | Inputs, lock file, state coordinates, or planned changes changed after approval. | Review the change; do not bypass the comparison or deletion/replacement rejection. |

For local tool failures, run `scripts/test/validate.sh`. For a safe synthetic SSE self-test, follow [load testing](load-testing.md); it proves only the local tool path.

## macOS/Linux helper diagnostics

| Symptom | Check and recovery |
| --- | --- |
| `az is required` | Azure CLI must be on the **helper child's** PATH. A GUI launch on macOS may not inherit a terminal's Homebrew PATH. Fix the approved launch environment and restart; do not copy caches or add fallback credentials. |
| `APIM_AUDIENCE and APIM_TENANT_ID must be set` | Check managed settings and actual helper-child inheritance with scrubbing enabled. For a standalone check, explicitly export both nonsecret inputs; managed settings do not populate the parent shell. |
| `Unable to acquire access token` | The CLI failed or returned empty/malformed output. Check approved Azure sign-in, tenant, consent and account selection as the same OS user. The helper deliberately suppresses raw CLI errors and never logs in interactively. |
| Permission denied / helper not found | Use an absolute helper filename, executable by the user, with administrator-controlled parent directories. Regenerate settings for that path; do not pass a shell command as a helper filename or run Claude with sudo. |
| Models missing after discovery opt-in | Fully restart the client, verify effective discovery settings and absence of overriding model lists, then distinguish a slow/cold gateway inventory request from an authentication failure. A cached picker is not proof of live discovery; retain role pins while investigating. |

Use the [Terminal installation checks](claude-code-managed-settings.md#install-and-verify) without printing helper stdout. Do not enable shell tracing, dump the environment or decode tokens into logs. The POSIX helper currently has no internal acquisition deadline; an unresponsive Azure CLI can block it. Retain a bounded pilot/canary and investigate network/CLI health rather than claiming Windows helper timeout behavior applies on macOS/Linux.

## Windows helper diagnostics

The native Windows helper reports only a safe category and fixed guidance: `configuration_invalid` names the invalid parameter without its value; `azure_cli_not_found` and `process_start_failed` identify local CLI setup/start failures. `subscription_metadata_invalid` means the explicitly selected cached subscription did not pass the required user/tenant/cloud/state checks; no token request follows. `azure_cli_timeout` means the shared 15s acquisition budget expired (startup and bounded cleanup can add wall-clock time); `azure_cli_failed` includes only the numeric exit code. `stream_read_failed` means either private CLI stream could not be read to completion within the shorter bounded wait, `invalid_token_output` means stdout was not one valid raw token, and `internal_error` or `cleanup_failed` indicates a local helper failure. Keep raw CLI output, tokens, exception messages, environment dumps, and token claims out of support logs.

Distinguish **helper-process exit** from **caller EOF**. On the supported Windows PowerShell 5.1 baseline, an arbitrary descendant retaining extra inherited caller handles can delay capture completion even after the helper exits promptly with a fixed error. This existing pilot availability limitation is reproduced by the fake CLI; it has not been demonstrated with the normal installed Azure CLI. There is no end-to-end caller-completion guarantee for that inheritance case. The native suite requires process deadlines and output/redaction checks to pass and reports the separate caller-EOF availability check as an expected failure, not a pass. Revisit launch isolation if the installed CLI reproduces it; do not broaden process killing or weaken authentication checks as a workaround.

Without `-SubscriptionId`, an explicit tenant/resource request still uses the **global default subscription's cached account**, which may differ from the intended gateway account. The approved optional [Windows account selector](claude-code-managed-settings.md) validates the selected subscription's cached metadata, then requests its token without changing the global default or adding login/fallback behavior. An explicitly empty or invalid selector is an error, not a return to default-account behavior. This binds a cached account selection, not an immutable user identity; APIM authorization remains required. Do not change the global default merely to bind Desktop.

`conditional_access_auth_flow` includes the literal code `AADSTS530036` only when that standalone code occurs in a failed CLI invocation: Conditional Access rejected refresh-token reuse under authentication-flows checks. It can still occur with a verified subscription selector. An authorized operator should review the matched policy and **Original transfer method** in Entra sign-in evidence before choosing an approved interactive flow. Another login may not resolve this, and increasing the timeout is not a remedy. This diagnostic alone does not establish which live policy or original sign-in flow caused the rejection. Do not disable WAM/Conditional Access, clear caches, force device code, use fallback credentials, or change the global default subscription or helper TTL as a workaround. Interactive retry stays outside the helper. After an approved sign-in or configuration correction, restart the client to retrigger the helper; do not add automatic retries or change its TTL. Native fake-CLI tests are not evidence of an installed-helper or live sign-in pilot.
